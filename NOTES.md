# NOTES

rat-engine treats language as action under pressure.

The project exists to make a compact language discipline visible, testable, and transferable. It focuses on what a pass does: read the field, preserve signal, reduce distortion, choose a move, and return an artifact.

## transfer

Transfer means the method can run outside its original context.

A transferable engine should work on ordinary inputs: vague plans, overloaded messages, unsupported claims, ornate phrasing, practical drafts, conflict, and missing context.

Transfer should be tested through output. A good result is usable, not merely familiar in style.

## compression

Compression removes excess while preserving structure.

Good compression keeps the load-bearing distinctions intact. It reduces noise, not meaning.

## tone

Tone is structural when it changes meaning, pressure, trust, or use.

Tone should serve the artifact. Wit, warmth, sharpness, and restraint are useful when they improve handling of the object.

## metaphor

Metaphor is an instrument.

It can locate, clarify, compress, or carry pressure. It should not substitute for evidence.

## privacy

Public material should expose method, not private origin.

A public example can preserve a pattern while changing names, removing identifying details, shortening context, and keeping the object intact.

## local testing

Local models should be tested with the same input set when possible.

Compare outputs by object, structure, signal, distortion, move fit, artifact, and language.

Failure is useful when it shows where the engine loses shape.

## maintenance

Keep the public engine small enough to govern.

Add examples when they clarify use. Add rules when they prevent repeated failure. Cut anything that only makes the project feel larger.
